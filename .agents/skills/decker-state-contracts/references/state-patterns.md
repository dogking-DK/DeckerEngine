# 已有状态处理模式

只阅读当前操作适用的部分。这里保存检查方法；具体限制、字段和 API 以链接的模块设计为准。

## 内存编辑与历史

依据：[Scene](../../../../spec/design/scene.md)、[服务事务](../../../../spec/design/application-services.md)。

- 先检查会话身份和 revision，防止重新加载旧版本后错误地接受过期编辑。
- 候选内容在提交前完成校验，失败保留真实文档及历史；事务中的多步编辑作为一个提交。
- 区分内容与计数器：undo/redo 恢复内容，真实 revision 继续单调递增；检查上限不能回绕。
- 明确 no-op 的比较语义。归一化或浮点往返不应无意触发新的编辑；相关测试使用非平凡数值。
- 历史准备和预算检查在真实提交之前；新编辑、no-op、保存和会话替换对 redo 的影响各自明确。

典型证据：批内后续操作失败后，前面操作未出现在真实状态；
undo 后恢复相同 ID/层级；原值写回不增加 revision。具体实现案例留在测试中。

## 保存与加载

依据：[IO](../../../../spec/design/foundation-io.md)、[场景持久化](../../../../spec/design/scene.md)。

- 加载先完整构建候选文档，成功后替换所有者；失败时当前文档仍可用。
- 保存使用一致快照；只有保存的版本仍对应当前文档状态时，才确认干净状态。
- 写入临时文件、完成检查和验证之后替换；主错误与清理错误分开报告，不能清理非本次拥有的文件。
- 明确替换前后的外部效果，不能承诺多文件原子性、任意平台或断电持久化。
- 错误响应或响应丢失不总能证明操作未执行；调用者需要查询状态时，文档应说明恢复方法。

典型证据：保存旧快照后新修改仍 dirty；失败重载保留原实体；
替换前失败保留旧字节并按约定清理临时文件。

## 异步发布、取消与关闭

依据：[Jobs](../../../../spec/design/foundation-jobs.md)、[异步资产](../../../../spec/design/assets-runtime.md)、
[Runtime](../../../../spec/design/runtime.md)、[Memory](../../../../spec/design/foundation-memory.md)。

- worker 构造候选，owner 线程在发布点重新检查会话/代际和取消状态；后台完成不等于业务结果已经可见。
- 明确取消请求的接受点及终态；取消与发布竞争时只允许一种结果，不把协作取消承诺为立即中断或硬截止。
- 跨线程传递拥有型结果和路由凭据；scratch、线程局部 pool、TLS 帧及借用引用不能随任务逃逸。
- 关闭先拒绝新工作，再取消/唤醒并 join；候选、线程 context、heap 按所有权顺序释放。已有外部拥有型结果的寿命单独说明。
- 队列满、完成积压和终态保留都应有明确上限；普通任务失败与宿主基础设施致命错误分别传播。

典型证据：旧代结果不能发布；输入空闲仍完成 owner 发布；取消竞争只产生一个终态；
满队列/等待中的 worker 可以退出；外部结果和 weak 控制块延迟释放时资源仍有效。

## 缓存发布与持久恢复

依据：[资产缓存与登记](../../../../spec/design/assets-runtime.md)、[IO](../../../../spec/design/foundation-io.md)。

- 区分产物准备与 current/清单切换，检查内容键、依赖快照和旧版本；多个文件有各自提交点。
- 发布前失败保留旧可用版本；发布后发生错误时说明已经生效的外部状态及查询/恢复入口。
- 持久恢复信息描述可以重放的步骤，跨进程测试覆盖各中断点；不能把同进程补偿当作断电原子性。
- 清理限定在当前缓存拥有的路径，明确进行中的候选、current 与仍被引用数据的保护规则。

典型证据：依赖内容变化使旧 key 失效；中途写入失败不暴露半份产物；重启恢复身份一致；
失败后的再次导入可成功，清理不触及目录外文件。具体故障点与格式约定保留在模块测试和设计中。
