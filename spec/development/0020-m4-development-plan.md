## 阶段完成条件

- 同一源重复导入与合法改名保留 AssetId；Scene 保存和重载只依赖稳定引用。
- 一个明确支持的静态 glTF 资产包含网格、基础材质和图片，离线工具与 Runtime 复用同一管线。
- 内容、参数和依赖变化导致缓存失效；删除可重建缓存不会丢失身份。
- JobId 能查询/等待/取消；CPU Ready 在数据实际发布后报告，失败、取消、关闭均有明确结果。
- 源/.meta/工程清单与缓存职责清楚；失败不会把半成品标记 Ready，恢复操作不破坏未知文件。
- CPU-only 可运行；不把 GPU Ready、渲染截图、多格式、文件监视或跨平台声明为 M4 交付。

## 验证策略

默认 Debug、目标功能及直接受影响链路，使用定向验证 skill；新增测试 target/名称随实现补入参考。
M4.1 重点为身份、Project 和文件失败保护；M4.2 为数据与 assetc；M4.3 为缓存；M4.4 为队列、
资产状态、相关 Runtime/stdio。只有改动确实影响优化或构建配置才补 Release/独立配置。
最终用自制有来源的小型夹具跑“登记 → 导入 → 加载 → 查询 Ready → 改依赖 → 重建 → 关闭 → 重启”；
加入损坏输入、过期目录 guard、取消与退出，不以随机等待代替同步检查。
